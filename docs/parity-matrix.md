## Parity matrix

| Feature area | Documented Quarto behavior / source | Current `uv-python` support | Slice 3 target | Deferred / later | Hard out-of-scope rationale |
| --- | --- | --- | --- | --- | --- |
| Execution engine binding and explicit opt-in | Quarto auto-binds `.qmd` to Knitr when `{r}` is found, Jupyter when other executable code is found, no engine when no executable blocks are found, and permits override with `engine`; mixed `{python}` plus `{r}` auto-binds to Knitr/reticulate. Source: execution options / Engine Binding. | Explicit opt-in only. `claimsLanguage()` returns `false`; docs require `engine: uv-python`; smoke asserts `examples/no-engine.qmd` is not claimed. | Keep explicit opt-in through `engine: uv-python`; do not auto-claim ordinary Python docs in Slice 3. | Possible later packaging/install story or opt-in project template. | Mixed-engine R/Python documents are out of scope because Quarto selects one engine and this extension should not become a dispatcher for Knitr/Jupyter. |
| `eval` | `eval: false` prevents execution and normally echoes code. Source: execution options / Output Options. | Implemented for supported static subset: document-level merged `execute.eval` defaults plus chunk-local override; runner skips execution and renderer can still echo source. | Completed in Phase 3 for boolean `true/false`. | Non-boolean condition expressions and format-conditional execution helpers. | Full Knitr-style expression-based `eval` is engine-specific and not part of the static uv-native contract. |
| `echo` | `echo` includes source code in output; can be set globally or per block. Source: execution options / Output Options. | Implemented for `true`, `false`, and `fenced`, with document-level defaults and chunk override. | Completed in Phase 3 for supported values. | Code-fold/styling edge cases across formats. | Full Quarto HTML code-tools parity is outside the engine slice unless needed by static validation. |
| `include` | `include: false` suppresses all code and result output while still executing. Source: execution options / Output Options. | Implemented with document-level default plus chunk override; renderer returns no markdown while runner still executes and shared state persists. | Completed in Phase 3 for boolean `true/false`. | None beyond option model. | N/A. |
| `output` | `output` controls inclusion of results; documented values include `true`, `false`, and `asis`. Source: execution options / Output Options and Raw Output. | Implemented for `true`, `false`, and `asis`; `asis` inserts stdout as raw Markdown while stderr/warnings/errors remain fenced diagnostics. | Completed in Phase 3 for supported values. | More granular output classes/styling. | Arbitrary MIME-bundle output parity is out of scope because it implies Jupyter/IPython display compatibility. |
| `warning` | `warning` controls inclusion of warnings. Source: execution options / Output Options. | Implemented as explicit warning events from Python's warnings subsystem. `warning: false` suppresses warning events but does not suppress ordinary stderr. | Completed in Phase 3 for boolean `true/false`. | Fine-grained warning categories/filters. | Full IPython warning formatting parity is out of scope. |
| `error` | `error: true` includes errors and does not halt processing; default behavior halts on errors. Source: execution options / Output Options. | Implemented with document-level default plus chunk override. Disallowed errors fail render; allowed errors render fenced tracebacks and execution continues. Smoke covers both paths. | Preserved in Phase 3 with ordered error events. | Cleaner traceback formatting and path redaction. | Exact Jupyter traceback rich rendering is out of scope. |
| `echo: fenced` | Renders the original executable fenced block, including options except `echo: fenced`, for tutorials; works globally or per block. Source: execution options / Fenced Echo. | Implemented as a displayed Markdown source block containing a non-executable `{python}` fence and supported `#|` options except `echo: fenced`; code still executes once unless `eval: false`. | Completed in Phase 3. | Styling and all option-preservation edge cases. | N/A; feasible static feature. |
| `output: asis` | Emits raw Markdown without Quarto's enclosing output divs; Jupyter can also use `IPython.display.Markdown`. Source: execution options / Raw Output. | Implemented for stdout raw Markdown. Phase 4 also adds the no-Jupyter `uv_python_runtime` display API for explicit Markdown/HTML display events independent of `output: asis`. | Completed in Phase 3 for stdout; display runtime completed in Phase 4. | Cross-format raw HTML/Markdown edge cases. | Unsafe implicit raw rendering is out of scope; raw output must be explicit author-trusted output. |
| Inline code | Quarto supports inline code syntax such as `` `{python} radius` `` for Jupyter, Knitr, and OJS; inline output is escaped by default; markdown inline output needs engine-specific wrapper; escaped forms include `` `{{python}} x` `` and extra backticks; inline code is not supported in YAML. Source: inline code docs. | Implemented for Markdown prose: single-backtick `` `{python} expr` `` evaluates in source order using the shared namespace; `` `{{python}} x` `` and extra-backtick literal forms are preserved; YAML/front matter is not scanned. Plain text is escaped, and explicit `Markdown`/`HTML` wrappers render rich inline output. | Completed in Phase 7 for expression-only static inline execution. | Broader inline rich display edge cases and non-expression semantics. | Jupyter protocol compatibility for complex libraries/multiprocessing inline behavior is out of scope. |
| stdout | Quarto/Jupyter renders cell stdout in output blocks; `output` and `include` control visibility. Source: execution options and Python docs. | Implemented as ordered `stdout` events captured with `contextlib.redirect_stdout`; rendered as fenced `.text .uv-python-stdout` by default and raw Markdown only under `output: asis`. | Completed in Phase 2/3 and validated in Phase 8. | Exact interleaving with stderr if Python buffering prevents reliable ordering. | Exact terminal/Jupyter stream interleaving may be impossible without a more invasive capture mechanism. |
| stderr | Quarto/Jupyter can show stderr-like stream output; warnings/errors have dedicated controls. Source: execution options. | Implemented as ordered `stderr` events captured with `contextlib.redirect_stderr`; rendered as fenced `.text .uv-python-stderr`. Ordinary stderr is not suppressed by `warning: false`. | Completed in Phase 2/3 and validated in Phase 8. | Styling and severity distinctions. | Exact stream interleaving with stdout remains documented-limited. |
| Python warnings | Quarto has `warning` as a first-class execution option. Source: execution options. | Captured as explicit warning events and rendered separately from ordinary stderr; `warning: false` suppresses only warning events. | Completed in Phase 3. | Warning category/location formatting. | Full IPython warning display semantics out of scope. |
| Errors / tracebacks | `error: true` includes errors and continues; default halts. Source: execution options. | Implemented as ordered `error` events with chunk/inline association. Allowed errors render fenced tracebacks and continue; disallowed chunk errors and inline exceptions fail the render with runner diagnostics. | Completed in Phase 2/3/7 and validated in Phase 8. | Cleaner user-facing tracebacks. | Exact notebook traceback MIME output out of scope. |
| Last-expression display | Jupyter defaults to `last_expr` shell interactivity; `ipynb-shell-interactivity` can change behavior. Source: execution options / Jupyter Options / Expression Printing. | Implemented for the final top-level expression in each chunk. `None` results and assignment-only chunks emit no expression output; multiple expression statements display only the last one. | Completed in Phase 4 for narrow `last_expr` behavior. | Additional `ipynb-shell-interactivity` modes. | Full IPython AST/session behavior is out of scope. |
| Markdown display | Quarto Jupyter examples use `IPython.display.Markdown` for raw Markdown output and tables. Sources: execution options / Raw Output; tables / Computations. | Implemented through `uv_python_runtime.display(Markdown(...))`, `_repr_markdown_()`, and `to_markdown()` as raw Markdown display events. Explicit Markdown pipe tables can also receive single-table `tbl-cap`/`tbl-*` metadata. | Completed in Phase 4/5 and validated in Phase 8. | Broader dataframe protocols and complex table layouts. | Importing or emulating IPython just for display is out of scope. |
| HTML display | Quarto table docs describe raw HTML table processing and Jupyter/IPython display can emit HTML. Sources: tables / HTML Tables and Python docs. | Implemented through `uv_python_runtime.display(HTML(...))`, `_repr_html_()`, and `to_html()` as author-trusted raw HTML for static HTML output. `uv-python` does not sanitize HTML. | Completed in Phase 4 with documented cross-format limitations. | HTML table processing compatibility experiments. | Arbitrary MIME-bundle and widget HTML/JS protocols are out of scope. |
| Matplotlib and plotnine figures | Quarto Python/Jupyter supports matplotlib figures; document-level `fig-width`/`fig-height` set matplotlib `figure.figsize`; `fig-format`/`fig-dpi` are execution context fields. Sources: Python docs; execution options / Figure Options; execute-info docs. plotnine documents `ggplot.draw(show=False)` returning a matplotlib `Figure`. | Captures open matplotlib figures at chunk end via Agg. Document/format `fig-width`, `fig-height`, `fig-dpi`, and `fig-format` are applied to matplotlib defaults/savefig for each chunk; `png` and `svg` are supported and Quarto's `retina` default is treated as PNG. Chunk-level figure settings override document defaults as uv-python extension behavior. Optional plotnine `ggplot` objects are drawn statically with `draw(show=False)` and saved through the same figure event path, including direct capture of returned figures. Repeated renders clear only the active format namespace under `*_files/uv-python/<format>/`. | Completed in Phase 6 for static PNG/SVG matplotlib assets; optional static plotnine rendering added in the ecosystem slice. | Other formats and format-specific non-HTML defaults; exact ggplot2/theme parity. | Interactive figures and Jupyter display protocols are out of scope. |
| Figure captions, crossrefs, alt text, sizing | Code figures can use `label` with `fig-`, `fig-cap`, `fig-alt`, `fig-link`, `fig-align`; computational figure layout/subcaptions are documented. Sources: figures / Cross References and Computations; execution options / Caption and Alt Text. | Implemented for static matplotlib image Markdown: `fig-cap` is the only source of visible figure captions; figures without `fig-cap` keep alt text as image metadata only. `label: fig-*` plus `fig-cap` makes single figures cross-referenceable, and `fig-alt`, `fig-align`, `fig-link`, `width`, and `height` are emitted as Pandoc/Quarto image metadata. Multiple figures in one chunk render in stable figure-number order; `fig-cap` lists must match figure count, while a scalar caption is applied to each unlabeled figure. | Completed in Phase 6 for basic static figure metadata and multi-figure output. | Multi-figure labels/layouts, `fig-subcap`, complex `layout`, dark/light `renderings`, LaTeX `fig-pos`/`fig-env`. | Full figure layout parity is large and not necessary for first static parity slice. |
| Tables / dataframes | Quarto supports markdown tables, computational tables, `tbl-cap`, `tbl-` labels, subcaptions, and IPython Markdown/tabulate examples; HTML table processing can convert raw HTML tables across formats. Source: tables docs. pandas documents `to_markdown()` as requiring `tabulate`; polars documents `DataFrame.to_dicts()` and `Series.to_list()` native extraction. | Implemented for explicit `display(Markdown(...))` pipe tables and optional pandas/polars `DataFrame`/`Series` rendering. Dataframe objects are detected before generic HTML/Markdown fallbacks and rendered by an internal dependency-free pipe-table formatter. A chunk with one Markdown table display event may use `tbl-cap` and a `tbl-*` `label`; the renderer appends Pandoc caption syntax and rejects multiple table-like Markdown display events as ambiguous. Literal cell pipes are encoded as `&#124;`. | Completed in Phase 5 for the minimal dependency-free single-table path; optional pandas/polars table rendering added in the ecosystem slice. | pandas Styler, MultiIndex parity beyond stringification, polars LazyFrame auto-collect, advanced styling/dtypes, HTML table experiments, subtables/panels, multiple-table layouts. | Full dataframe protocol and arbitrary HTML table compatibility would create dependency and MIME sprawl. |
| Params | Jupyter parameters use Papermill-style tagged parameter cell and top-level injected variables; Knitr and Julia use `params` YAML with engine-specific access; CLI supports `-P` and `--execute-params`. Source: parameters docs. | Implemented as uv-python-specific Python global `params`. YAML `params` from metadata are merged with `ExecuteOptions.params`, and CLI/execute params override YAML keys. No top-level variable injection is performed. | Completed in Phase 7. | Top-level variable injection only if explicitly designed. | Papermill/Jupyter cell injection semantics are out of scope because there is no notebook execution model. |
| `QUARTO_EXECUTE_INFO` | Quarto sets `QUARTO_EXECUTE_INFO` to a JSON file with `document-path` and `format` (`identifier`, `execute`, `render`, `pandoc`, `language`, `metadata`). Source: execute-info docs. | Implemented: uv-python writes a JSON file and sets `QUARTO_EXECUTE_INFO` for the runner. It includes document path and active format identifier/execute/render/pandoc/language/metadata. uv-python does not synthesize `QUARTO_PROJECT_DIR`, but the inherited Quarto render environment may contain it. | Completed in Phase 7. | Additional execute-info fields only if Quarto exposes and docs require them. | None, but schema is uv-python-provided for this custom engine. |
| Caching / freeze | Python/Jupyter caching uses Jupyter Cache; project `freeze` stores executed results in `_freeze` and reuses them for global project renders; incremental single-document renders always execute. Sources: Python / Caching; projects / Managing Execution. | Engine discovery sets `canFreeze: false`; no cache implementation. Generated `.quarto/_freeze` from ordinary Quarto behavior may exist for non-engine docs, but uv-python does not promise freeze/cache parity. | Keep out of Slice 3 feature implementation except documenting boundaries. | uv-native cache design; possible future `canFreeze` investigation. | Jupyter Cache parity is out of scope because it depends on notebook machinery. |
| `.ipynb` rendering | Quarto renders `.ipynb`; notebooks are not executed by default unless `--execute` or YAML enables execution. Source: Python docs and project execution docs. | Unsupported. `validExtensions()` returns empty; project targets `.qmd` docs. | No Slice 3 target. | None planned. | `.ipynb` execution/rendering belongs to Quarto's Jupyter path, not this engine. |
| Widgets and arbitrary MIME bundles | Quarto/Jupyter supports rich notebook outputs and widgets through Jupyter infrastructure. Source: Python docs and Jupyter docs referenced there. | Unsupported; project intentionally has no Jupyter dependencies. | No Slice 3 target. | Possibly static HTML-only experiments for specific libraries after approval. | Widgets/MIME bundles require Jupyter/IPython protocols and are a prime non-goal. |
| IDE/kernels/live execution | Positron, VS Code, and JupyterLab integrations provide Python code completion, cell execution, notebook editing, and previews around Python/Jupyter workflows. Source: Python docs / Positron, VS Code, Jupyter Lab, Kernel Daemon. | Unsupported. This engine only participates in `quarto render`/preview as a Quarto execution engine. | No Slice 3 target. | Documentation can explain when users should choose Jupyter. | Live kernel sessions, completions, debugging, and daemon behavior require IDE/Jupyter integration, outside static rendering. |
| Mixed-engine docs | Quarto can bind mixed `{r}` and `{python}` to Knitr/reticulate; only one execution engine is selected for a document. Source: execution options / Engine Binding; literature review notes one-engine constraint. | Explicit uv-python engine handles only `{python}` cells and passes other markdown/raw cells through. | Keep single-engine Python-only scope. | None unless project direction changes. | Delegating to multiple engines would make `uv-python` an engine coordinator rather than a simple uv-native Python engine. |
